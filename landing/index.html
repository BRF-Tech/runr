Kodu yapıştır → Deploy

Platform dependency'leri kurar, Go'yu derler, imajı cluster içinde Kaniko ile üretir ve Knative'e teslim eder.

1Web editörde kodu yaz ya da git push — her değişiklik bir versiyon

Arka planda otomatik: dependency kurulumu ya da Go derlemesi → Kubernetes Job olarak Kaniko build (linux/amd64) → region registry'sine push → Knative revision. Dependency'si olmayan kod build'e hiç girmez, doğrudan ConfigMap'ten yayına çıkar.

⚡ ~3 sn (bağımlılıksız) · ~23 sn (build'li) / değişiklik

RunR ölçümü: v0.4.2, tek düğümlü k3s (8 vCPU, 16 GB); kaydetmeden yeni kodun yanıt vermesine kadar medyan (n=3). Bağımlılıksız 2,7 sn (2,7–3,7 sn); build'li 23,0 sn (22,0–25,0 sn; Kaniko, Node + 1 npm bağımlılığı, temel imajlar region registry önbelleğinden). Projenin ilk build'ine bir kerelik temel imaj çekme eklenir.

Dahili runtime'lar

Python Node.js Go PHP PyTorch TensorFlow

Runtime imajları upstream'i takip eder: ömrünü doldurmamış (EOL olmayan) her sürüm hazır gelir, her proje kendi sürümünü seçer.

Her dil: runtime plugin'leri

C Rust Bash Q sizin diliniz

Bir runtime, bir runtime.yaml manifesti ve bir imajdır. Universal wrapper (runr-wrapper) HTTP isteklerini, kuyruk mesajlarını ve zamanlama tetiklerini stdin / stdout üzerinden çağrılara çevirir; http, exec ve persistent modları. Platform yöneticileri ve organizasyonlar kendi runtime'larını kaydeder; runr dev aynı imajlarla yerelde çalıştırır.

WebAssembly (Spin)

Rust Go (TinyGo) JavaScript / TypeScript Python wasm-exec: C / C++ · Zig · .wasm

Wasm fonksiyonları runwasi'nin Spin shim'i üzerinde Spin bileşeni olarak çalışır; region'ın Isolation sekmesinden tek tıkla kurulur. wasm-exec, her WASI komutunu Spin'in WAGI executor'ında çalıştırır.

⚡ Sıfırdan ilk yanıt: Rust 1,54 sn · JavaScript 2,12 sn

RunR ölçümü: v0.5.0, 2026-10-15, test VM'inde tek düğümlü k3s v1.34.11 (8 vCPU Broadwell, iç içe KVM, 15,6 GiB), Knative 1.21.3; Spin shim, 250m / 128 MiB, imaj düğümde, RunR'ın varsayılan scale-to-zero ayarı; VM içinden Traefik üzerinden HTTPS, her istekte yeni bağlantı; sıfır replikadan ilk tam HTTPS yanıtına medyan (p90), her biri n=12: Rust 1,54 sn (1,84), JavaScript 2,12 sn (2,58); sıcak istek medyanı 9 / 11 ms (n=100).

SANDBOX & RUNTIME İZOLASYON

Container'ın altında bir şey değiştirmek istediğinizde.

Her region, XaaS, FaaS, CaaS ve build job'larını RuntimeClass üzerinden ayrı ayrı bir container runtime'a eşler: varsayılan runc, kurulduktan sonra gVisor ya da Kata. gVisor syscall'ları intercept eder, Kata her pod'u kendi mikro-VM'inde çalıştırır, Firecracker (AWS Lambda'nın da kullandığı) en yalın mikro-VM'i sunar. Aynı izolasyon Sandbox API'nin sandbox'larını da korur.

Containerd shim seçimi — proje tipi başına

Her region XaaS, FaaS, CaaS ve build job'larını ayrı ayrı bir runtime'a eşler — varsayılan runc; gVisor ya da bir Kata hypervisor'ı kurulduğu anda seçilebilir. Deploy sırasında Knative manifestine uygun runtimeClassName (gvisor, kata-clh, kata-qemu, kata-dragonball, kata-fc) otomatik yazılır; WebAssembly fonksiyonları wasmtime-spin-v2 ile Spin shim'inde çalışır.

🔧

Cilium sandbox network fix — kendi platformumuzda çözdük

Sandbox pod'lar varsayılan olarak host-net namespace'inden ClusterIP servislerine erişemez (Cilium upstream bug). RunR cluster'a bpf-lb-sock-hostns-only: true patch'ini otomatik uygular — çalışan cluster'larda, kesintisiz.

GEÇİŞ

Cloud'dan RunR'a — aylar değil saatler.

Mevcut iş yüklerinizi RunR'a taşımanın ne kadar iş gerektirdiğini görün.

AWS Lambda→RunR

Handler'lar XaaS'a 1:1 eşleşir. AWS SDK kaldırın, kodu yapıştırın, deploy edin.

Az kod değişikliği

GCP Cloud Run→RunR

Cloud Run zaten Knative — RunR de Knative. Container'lar olduğu gibi çalışır.

Kod değişikliği yok

Azure Functions→RunR

SDK binding'leri kaldırın, standart HTTP handler'lara dönüştürün.

Orta düzey kod değişikliği

Vercel→RunR

Standart Node.js handler. FaaS'a kopyalayın, package.json ekleyin, deploy.

Az kod değişikliği

Heroku→RunR

Container'a paketleyin, CaaS olarak deploy edin. Scale-to-zero dahil; boştaki kapasite diğer iş yüklerine kalır.

Dockerfile ekleyin

Docker Compose→RunR

Her servis bir CaaS projesi. Aynı image, aynı env. Artık auto-scale var.

Kod değişikliği yok

AWS ECS/Fargate→RunR

Task definition'lar zaten container tanımı. Aynı image, CaaS'a verin.

Kod değişikliği yok

Fly.io / Render→RunR

Standart Docker olduğu gibi çalışır. fly.toml veya render.yaml gerekmez.

Kod değişikliği yok

K8s YAML→RunR

Image'larınız zaten hazır. UI'dan deploy edin, YAML yazmayın.

Kod değişikliği yok
KURULUM

Kurun, bir cluster bağlayın, deploy edin.

RunR bir yazılımdır, barındırılan bir hizmet değil: kontrol düzlemi ve tüm region'lar sizin işlettiğiniz altyapıda çalışır — bare metal, private cloud ya da yönetilen Kubernetes; internete bağlı ya da air-gapped.

Helm Kubernetes

Kontrol düzlemi tek bir Helm chart: gateway, UI, API, worker'lar, scheduler, Reverb; kendi servislerinizi göstermezseniz PostgreSQL ve Redis de.

git clone https://github.com/brf-tech/runr.git
cd core
helm upgrade --install runr ./helm \
  -n runr --create-namespace \
  --set domain=runr.example.com
Helm ile kurulum →

Docker Compose tek sunucu

Hazır imajlarla tek makinede üretim kurulumu; internetsiz (air-gapped) sunucular dahil.

docker load -i runr-images.tar
cp .env.example .env
cp api.env.example api.env   # + APP_KEY
docker compose up -d
docker compose run --rm migrator
Tek sunucu kurulum rehberi →

cd hello

runr deploy
